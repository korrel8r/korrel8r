# Quick Rules (Compiled Rules)

Quick rules are correlation rules compiled into the `korrel8r` binary as Go code.
They are written as [quicktemplate](https://github.com/valyala/quicktemplate) templates in this
directory (`*.qtpl`) and compiled to Go by `make generate`.

Quick rules are the compile-time alternative to
[configuration rules](../../../etc/korrel8r/rules/README.md), which are loaded from YAML files and
use Go `text/template`.

> **Edit only `*.qtpl`.** The `*.qtpl.go` and `applyfuncs.go` files are generated — see
> [Compiling](#compiling).

## Quick Rules vs Configuration Rules

| | Quick rules (`*.qtpl`) | Configuration rules (`etc/korrel8r/rules/*.yaml`) |
|---|---|---|
| Source | Compiled into the binary | YAML files loaded at runtime |
| Change requires | Rebuild (`make generate` + build) | No rebuild |
| Template language | [quicktemplate](https://github.com/valyala/quicktemplate) (`{% code %}` runs Go) | Go `text/template` |
| Type safety | Full Go type checking in `{% code %}` | Template only |
| Performance | Faster (pre-compiled functions) | Slower (parsed templates) |
| Use for | Hot paths, complex Go logic | Quick changes, user-installed rules |

Both produce the same thing: a rule linking start classes to goal classes, applied to a start
object to generate goal queries. The rule registry metadata uses the same YAML schema as a
configuration rule.

## Directory Layout

- `*.qtpl` — Quicktemplate rule sources. **Edit these.**
- `*.qtpl.go` — Generated by `qtc`. **Do not edit.**
- `applyfuncs.go` — Generated `applyFuncs` map. **Do not edit.**
- `quickrules.go` — Parses rule annotations and builds `korrel8r.Rule` values.
- `quickrules_test.go` — Tests for applying rules and parsing annotations.

## Writing a Quick Rule

A rule is a `{% func %}` template preceded by a YAML annotation. The annotation is the rule
registry metadata; the function body generates the goal query. Together they look like this:

```text
# MetricToPod creates a k8s Pod query from the pod labels of a metric.
name: MetricToPod
start:
  domain: metric
  classes: [metric]
goal:
  domain: k8s
  classes: [Pod]

{% func MetricToPod(o interface{}) %}
{% code
	m := o.(metric.Object)
	ns := m.Labels["k8s_namespace_name"]
	if ns == "" {
		ns = m.Labels["namespace"]
	}
	name := m.Labels["k8s_pod_name"]
	if name == "" {
		name = m.Labels["pod"]
	}
	if ns == "" || name == "" {
		rules.Fail("MetricToPod: missing required pod labels: %v", m.Labels)
	}
%}
k8s:Pod:{"namespace":{%q= ns %},"name":{%q= name %}}
{% endfunc %}
```

`{% func RuleName(o interface{}) %}` receives the start object. Use a type assertion in a
`{% code %}` block to access its domain-specific fields.

### Template Body

The function body writes the goal query strings to the output; each non-blank line becomes one
goal query. Supported constructs:

- `{% code %}` — an arbitrary Go block, e.g. type assertions, label lookups, loops.
- `{%q= x %}` — writes `x` JSON-quoted, for safely embedding values in a query.
- `{%= x %}` — writes `x` (HTML-escaped).
- `rules.Fail(format, args...)` — aborts the rule with an error instead of applying it.
  Used when the start object lacks the data the rule needs.
- A blank (whitespace-only) output means the rule does not apply to the start object.

#### Imports

Templates may import Go packages for use inside `{% code %}` blocks. Rule templates typically
import the start-object's domain package (for type assertions) and `pkg/rules` (for `rules.Fail`):

```text
{% package quickrules %}

{% import "github.com/korrel8r/korrel8r/pkg/domains/metric" %}
{% import "github.com/korrel8r/korrel8r/pkg/rules" %}
```

### Metadata (YAML annotation)

The bare text between two template blocks is a single YAML descriptor for the following rule,
using the same schema as a configuration rule; `#` lines are comments and may appear anywhere.
At startup `parseRuleAnnotations` (in `quickrules.go`) reads this metadata to build the rule
registry, and it verifies that:

- Every rule has a `name` that matches its `{% func %}` name exactly (the `applyFuncs` map is keyed
  by these names: `Name` maps to `Stream<Name>`).
- Rule names are unique across all `*.qtpl` files.
- `start` and `goal` each specify a `domain` and at least one `class`.

## Compiling

`make generate` compiles every `*.qtpl` with `qtc` (producing `*.qtpl.go`) and regenerates
`applyfuncs.go` from the `{% func %}` declarations with `hack/gen-applyfuncs.sh`:

```bash
make generate   # also runs from 'make lint'
go build ./...
```

Then add test cases and rebuild. Never edit the generated files by hand.

## Testing

Add table-driven cases to `quickrules_test.go`: a start object in, the expected goal query
strings out. Run:

```bash
go test ./pkg/rules/quickrules/
go test ./etc/korrel8r/rules/   # exercises compiled + configuration rules together
```

## Loading Quick Rules

`quickrules.Rules(d)` returns the compiled rules for a set of domains. The `korrel8r` CLI adds
them to every engine (see `cmd/korrel8r/main.go`) alongside configuration rules, so a quick rule
takes effect as soon as it is compiled in.
